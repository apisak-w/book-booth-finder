# Home screen tabs with event posters Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the flat event list at `/` with On now, Coming up and Past tabs, and give each event card an optional poster strip, opening hours and a status-specific body.

**Architecture:** Pure date helpers go in `src/lib/core/status.ts`. `event.json` gains optional `poster` and `hours`. The catalog checks the poster file and reads its size with `sharp` at build time. The page turns the file name into a content-hashed URL through a Vite glob. The page renders tabs and cards only after mount, when `now` is known. Before that it keeps a placeholder of the same height.

**Tech Stack:** SvelteKit 2 (Svelte 5 runes), adapter-static, Bun test, Playwright 1.63 (`page.clock`), Zod, sharp.

**Spec:** `docs/superpowers/specs/2026-10-24-home-tabs-design.md`

## Global Constraints

- Every guest-facing string exists in `th` and `en`. Plain verbs, sentence case, no exclamation marks.
- `src/lib/core/` stays free of DOM, Svelte and Zod. Zod and sharp never reach the client bundle.
- No new colours. Use the tokens in `src/lib/styles/app.css`. The dark-mode selected tab is `#9fc2ff` (dark `--ink`) with `--panel` text.
- Poster: `poster.jpg` or `poster.webp` in the event folder, at most 1100 px wide, at most 100 KB.
- Hours: `{ "open": "HH:MM", "close": "HH:MM" }`, 24-hour, `open` before `close`. Thai shows `10.00`, English shows `10:00`.
- Status stays date-based in the venue time zone (`eventStatus`). Hours never change it.
- The chosen tab is not saved. No new storage keys.
- `event.json` files stay oxfmt-clean (`tests/json-format.test.ts`).
- No verbose code comments. Conventional Commits with scopes `core`, `app`, `event`.

## Review Focus

1. A phone set to another time zone, for example UTC or a visitor's home zone. Day counts and "Opens in" must use the venue time zone (Task 1 test).
2. The last evening and the day before an event. At 23:30 Bangkok on the last day the card is still On now with "Day 10 of 10". The day before the start says "Opens tomorrow", not "Opens in 1 days" (Tasks 1 and 3 tests).
3. A missing, oversized or wrongly named poster. The build fails and names the file instead of shipping a broken image (Task 2 tests).
4. A poster that fails to load on weak data. The card keeps its height (blue strip) and shows no broken-image text, and the name and button stay usable (Task 5 e2e).
5. The long Thai National Book Fair name on a 390 px phone. It wraps inside the card with no horizontal page scroll (Task 5 e2e).

    2. A badge.
    3. The name.
    4. The venue.
    5. Live: hours (if any), then a progress bar with `dayOf` and `until(fmtRange(end, end, lang))`. Upcoming: the date range, then hours (if any). Past: the date range.
    6. Upcoming: `opensTomorrow` when `daysUntil` is 1, otherwise `opensIn(n)`. Past: `pastNote`.
    7. A `<span class="cta">` with `findBooth` (live), `previewMap` (upcoming) or `openMap` (past, secondary style).
